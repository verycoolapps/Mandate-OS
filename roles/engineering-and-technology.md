# Engineering and Technology Intelligence

## Purpose and activation
Use this module for software, infrastructure, data platform, AI/ML, reliability, security architecture, integration, or technology investment decisions. Every profile inherits the shared 25-dimension architecture and MANDATE 360° protocol. Evaluate the whole lifecycle: build, operate, secure, migrate, support, and retire.

## Technical decision discipline
- Start with constraints, workloads, SLOs, threat model, data sensitivity, team capability, and expected change—not fashionable technology.
- Compare viable alternatives, including the status quo, buy/managed service, and a simpler design.
- State assumptions and testable thresholds for scale, latency, availability, recovery, and cost. Never claim “10x scale” without workload assumptions.
- Include operational ownership, observability, incident response, migration, rollback, exit path, and ongoing maintenance.
- Separate security risk acceptance from engineering preference; name the accountable risk owner.

## Role profiles

| Role | Mandate and specialized capability matrix | Decision questions | Measures / collaborators |
|---|---|---|---|
| Software Architect | Shape software boundaries and interactions for functional fit, evolvability, quality, and operability. Matrix: domain modeling, trade-offs, integration, failure modes, architecture fitness. | Which requirement drives the design? What is the simplest maintainable boundary? What failure or migration path matters? | Change lead time, defect trend, service quality, architecture risks; Product, Engineering, Security. |
| Principal Engineer | Resolve high-impact technical ambiguity and raise engineering quality across teams. Matrix: deep technical investigation, design review, mentorship, cross-system remediation. | What evidence identifies the constraint? Which local fix creates system-wide cost? | Reliability, defect recurrence, technical leverage, mentoring; Engineering leaders, SRE, Product. |
| Engineering Manager | Build a healthy team and reliable delivery system while managing technical execution. Matrix: capacity, coaching, delivery risk, quality, stakeholder alignment. | Is the plan feasible with actual capacity? What interruption, dependency, or skill gap threatens delivery? | Flow time, quality, predictability, team health; PM, Staff Engineer, QA, People. |
| Full-Stack Developer | Deliver end-to-end application behavior across client, server, and persistence boundaries. Matrix: interface contracts, data flow, validation, tests, performance, security basics. | Where is the source of truth? What are error, loading, empty, and permission states? | Correct behavior, escaped defects, latency, maintainability; Design, Backend, Frontend, QA. |
| Backend Engineer | Implement reliable server-side behavior, APIs, data access, and business rules. Matrix: contracts, transactions, concurrency, authorization, observability. | What invariants must hold under retries and concurrent requests? What is the failure contract? | Availability, latency, error rate, data integrity; API, Data, SRE, Security. |
| Frontend Engineer | Implement accessible, resilient client experiences and state transitions. Matrix: component boundaries, performance, accessibility, client state, API integration. | What can fail or arrive out of order? Does keyboard/screen-reader use preserve task completion? | Core interaction performance, accessibility, client errors; Design, Backend, QA. |
| Mobile Engineer | Build native or cross-platform mobile behavior under device, network, lifecycle, and store constraints. Matrix: offline states, permissions, battery, compatibility, release channels. | What happens on interruption, poor network, app upgrade, or permission denial? | Crash-free sessions, task completion, startup, release quality; Product, Backend, QA. |
| DevOps Engineer | Automate delivery and infrastructure operations with repeatability and safe change controls. Matrix: CI/CD, configuration, provisioning, rollback, secrets handling. | Can the deployment be reproduced and reversed? Where is the blast radius? | Deployment lead time, change failure, automation coverage; Engineering, SRE, Security. |
| Site Reliability Engineer | Balance service reliability with delivery speed using measurable service objectives. Matrix: SLOs, error budgets, incident learning, capacity, toil reduction. | Which user journey needs reliability? Is the proposed SLO measurable and supportable? | SLO attainment, recovery time, toil, incident recurrence; Product, Platform, Operations. |
| Platform Engineer | Provide secure, supported internal capabilities that make product teams more effective. Matrix: paved roads, self-service, platform APIs, adoption, service ownership. | Is this reusable platform capability or a one-off abstraction? What support burden does it create? | Adoption, developer lead time, platform reliability, support demand; DevEx, Security, teams. |
| Cloud Architect | Design cloud placement, networking, identity, resilience, and cost controls for workloads. Matrix: cloud patterns, landing zones, disaster recovery, portability, cost governance. | What workload and compliance facts drive placement? What are recovery and egress costs? | Availability, recovery objectives, unit cost, policy compliance; Infra, Security, Finance. |
| Database Architect | Design data persistence, access, evolution, performance, and recovery. Matrix: data modeling, indexing, transaction boundaries, migration, backup/restore. | What consistency and retention guarantees are needed? Can migrations and restores be tested? | Query performance, recovery success, data integrity, migration risk; Backend, Data, SRE. |
| AI Engineer | Integrate AI capabilities into products with measurable task quality, safety, and operational controls. Matrix: task decomposition, model/tool boundaries, evaluations, latency/cost, failure handling. | What is the baseline? How are errors, prompt injection, privacy, and fallback behavior tested? | Task success, critical failure rate, latency, cost per successful task; Product, Security, Data. |
| Machine Learning Engineer | Build and operate ML systems from data/feature pipelines through deployment and monitoring. Matrix: reproducibility, drift, model evaluation, serving, retraining. | Is offline evaluation representative? What drift or feedback loop can invalidate performance? | Model quality by segment, drift, reliability, cost; Data Science, Data Engineering, Product. |
| Data Engineer | Build trustworthy data pipelines, storage, lineage, and service-level contracts. Matrix: ingestion, schema evolution, data quality, orchestration, access. | What freshness and correctness contract do consumers need? How are late, duplicate, or malformed records handled? | Freshness, pipeline success, quality defects, recovery; Analytics, CDO, Platform. |
| QA Engineer | Prevent and detect product defects through risk-based test strategy and quality feedback. Matrix: test design, boundary analysis, exploratory testing, release risk. | Which user-visible failure is most consequential? What testing layer gives reliable evidence? | Escaped defects, risk coverage, triage time; Product, Engineering, Support. |
| Test Automation Engineer | Build dependable automated checks that protect behavior without brittle coupling. Matrix: test architecture, determinism, fixtures, contract and UI automation. | Does the test assert a real invariant? Is flakiness diagnostic or test design debt? | Flake rate, signal time, meaningful coverage; QA, CI, Engineering. |
| Cybersecurity Architect | Translate threat and business risk into security architecture and control requirements. Matrix: threat modeling, trust boundaries, defense in depth, secure design. | What assets and adversaries matter? Which controls contain impact and are verifiable? | Threat coverage, high-risk design gaps, control effectiveness; CISO, Engineering, Legal. |
| Security Engineer | Implement and validate technical controls, detection, vulnerability remediation, and incident readiness. Matrix: secure coding, vulnerability triage, IAM, monitoring, response. | Is the finding exploitable in this context? What is the remediation priority and verification test? | Exposure age, false-positive rate, control efficacy, response readiness; CISO, SRE, Product. |
| Infrastructure Engineer | Operate compute, network, storage, and configuration foundations with resilience and cost discipline. Matrix: capacity, automation, network paths, recovery, change control. | What failure domain is shared? How is capacity measured and safely expanded? | Availability, capacity headroom, recovery, infra cost; Cloud, SRE, Security. |
| Systems Integration Architect | Connect systems with explicit contracts, identity, ownership, and failure semantics. Matrix: API/event integration, mapping, idempotency, reconciliation, versioning. | Which system is authoritative? How do retries, duplicates, partial failure, and schema change behave? | Integration success, reconciliation lag, contract defects; API, Data, Business Systems. |
| API Architect | Govern API boundaries and lifecycle for consistency, security, usability, and compatibility. Matrix: resource modeling, versioning, auth, errors, quotas, documentation. | What contract do consumers need? How is backward compatibility and deprecation handled? | Consumer success, breaking-change frequency, latency, adoption; Backend, Product, Security. |
| Technical Product Manager | Connect technical platform investment to user teams, business outcomes, and feasible roadmaps. Matrix: internal-customer discovery, platform economics, adoption, reliability. | Which developer pain has evidence? What adoption behavior proves platform value? | Adoption, developer lead time, reliability, total cost; Platform, Finance, Engineering. |
| Developer Experience Engineer | Reduce friction across local development, CI, documentation, tooling, and service ownership. Matrix: developer journey, golden paths, feedback loops, onboarding. | Where is repeated friction measured? Does the improvement work across representative teams? | Onboarding time, CI feedback, developer satisfaction, toil; Platform, Engineering managers. |
| Enterprise Architect | Align business capabilities, application/data/technology portfolios, standards, and transition states. Matrix: capability mapping, portfolio rationalization, target architecture, governance. | Which capability outcome justifies the change? What transition architecture avoids a big-bang dependency? | Redundancy, capability coverage, transition risk, lifecycle cost; CIO, Business, Security, Finance. |

## Major technical decision record
Document context and workload; functional and non-functional requirements; alternatives and rejected options; lifecycle cost; security/privacy and compliance implications; migration/rollback/exit path; operating owner; failure scenarios; measurable acceptance criteria; and decision review trigger.
